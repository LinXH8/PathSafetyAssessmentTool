## 7. Road-speed sigmoid (source: `Speed risk factors` sheet)

v2.13 cell `D4`–`D277` formula (verbatim, applied to every speed 1..276):

```
=1+27.82/(1+EXP(7.44925-0.13322*B<row>))
```

For mph (rows beyond ~150, speed encoded as `1000+mph`):

```
=1+27.82/(1+EXP(7.44925-0.13322*((B<row>-1000)*1.609344)))
```

Python (`get_road_speed_risk_factor` in `cyclerap_scoring.py:204`):

```python
return 1 + 27.82 / (1 + np.exp(5.84 - 0.091 * (round(speed) - 1)))
```

The numerator constant `27.82` matches; the exponent intercept (5.84 vs 7.44925)
and slope (0.091 vs 0.13322) **differ**, and Python rounds + subtracts 1 before
applying. The Excel header cells `I2=0.091` and `I3=5.84` are **legacy v2.10
constants** that are no longer used by the v2.13 formula (a comment cell
`F3="1"`, `F13="1.25"`, `F23="1.5"` labels the column "Risk V2.10"). Python
appears to have been derived from the legacy header rather than the active
formula.

## 8. line_of_sight — severity-only in v2.13 (correction)

An earlier draft of this audit claimed `line_of_sight` was absent from v2.13's
scoring formulas; that was wrong. The initial search only covered the `BZ`
conditional column and the `BR..CL` scoring summary. The actual severity
factor lives in column `CU`, which the search missed.

v2.13 reads "Line of Sight" from the following cells (all severity-only, no
conditional trigger):

| Cell | Component | Range that includes it |
|------|-----------|------------------------|
| CU4  | CM3       | `PRODUCT(CU3:CU15)` |
| CU18 | CM16/CM17 | `PRODUCT(CU17:CU25)` |
| CU43 | CM40/CM42 | `PRODUCT(CU42:CU54)` |

There is **no** `Line of Sight` reference in the `CQ` (conditional) columns of
any component, so it must not contribute to the `(1 + 0.1·Σcond)` exponent.

Python now matches: LOS appears in `cu_factors` / `cu16_factors` / `cu40_factors`
as a severity multiplier; the entry in `LOOKUP_TABLES['line_of_sight']` has
`cond: 0` so any latent `get_cond` call returns zero.
